# **The Evolution of the Industry**

You could open with something like this:

## **2022: Prompt Engineering**

```text
Human
 ↓
Prompt
 ↓
LLM
 ↓
Output
```

The conversation was:

“What is the perfect prompt?”

The obsession was:

- Role Prompting
- Chain of Thought
- Few-Shot Prompting
- Mega Prompts

The belief was:

If we write the right prompt, the model will perform magic.

---

## **2023: Prompt Engineering at Scale**

People started realizing something.

Prompts kept growing.

```text
50 lines
100 lines
500 lines
1000 lines
```

We started adding:

- Context
- Constraints
- Examples
- Rules
- Templates

And without realizing it…

We were writing specifications.

We just weren’t calling them that yet.

---

## **2024: Vibe Coding**

This is a good moment for a fun pause.

Ask:

How many people here have done Vibe Coding?

You’ll probably get several hands.

Define it:

Vibe Coding is when a developer keeps talking to the AI until something works.

```text
Prompt
↓
Code
↓
Prompt
↓
Code
↓
Fix
↓
Fix
↓
Fix
↓
It works
```

Advantages:

- Extremely fast
- Highly creative
- Excellent for exploration

Problems:

- Hard to reproduce
- Hard to scale
- Hard to delegate
- Hard to maintain

## **2025–2026: Spec-Driven Development**

This is where the major shift happens.

The industry discovers something.

We don’t want agents to be creative.

We want them to be consistent.

So the workflow becomes:

```text
Prompt
↓
PRD
↓
Specs
↓
Tasks
↓
Agent Execution
```

The goal changes.

Before:

“How do we write better prompts?”

Now:

“How do we describe intent more precisely?”


# **Connecting LEAD, LID, BEMA, SpecKit**

This is where you introduce the frameworks.

Not as tools.

But as responses to the same underlying problem.

All of them are trying to solve:

```text
Human Idea
↓
Ambiguity
↓
Clarification
↓
Structure
↓
Execution
```

The syntax changes.

The philosophy remains the same.

# **Answering the Easter Egg**

Later in the presentation, come back to the question.

What is the difference between a junior developer and a senior developer when both are using agents?

Most people will think:

The senior writes better prompts.

And your answer is:

No.

The senior formulates better problems.

Because they:

- Understand constraints
- Identify ambiguities
- Define success criteria
- Know which questions to ask

That is exactly what refinement is.

End with something like:

Two years ago, we thought the job was writing prompts.

Agents write code.
