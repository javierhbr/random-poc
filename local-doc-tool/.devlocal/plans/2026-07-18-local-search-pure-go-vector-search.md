# Plan: Pure-Go vector (semantic) search + kNN graph for `local-search`

## Context

The research doc `.devlocal/research/2026-07-18-sqliteai-sqlite-vector-turboquant.md` evaluates using SQLiteAI `sqlite-vector` + TurboQuant. Its own conclusion is that the extension route **requires CGO**, ships per-platform native `.dylib/.so/.dll`, hits macOS Gatekeeper, and carries an **Elastic License 2.0** — all of which invert `local-search`'s headline identity: a single pure-Go static binary that installs via one-line `curl` and cross-compiles to 5 platforms with no C toolchain (`code/README.md:33`, `:248`).

**Decision (user-confirmed):** prioritize simplicity for the final user → **stay pure Go, no CGO, no native extension.** Embeddings come from a **deterministic placeholder embedder** (no ML model). Because the corpus is low-thousands of docs, the doc's own perf analysis says exact vector scan is `<2 ms` and "not the bottleneck," so brute-force cosine **in Go** is sufficient — no `sqlite-vector`, no `modernc.org/sqlite/vec` needed. The binary, install.sh, and "no CGO" README claims all stay true.

Goal: prove an end-to-end semantic-search + kNN-graph pipeline as a POC without changing the tool's distribution story.

## Scope (all three, user-selected)

1. Core vector search (schema + embedder + index pass + query fusion)
2. kNN graph UI command (NetworkX node-link JSON)
3. Distribution — confirm it stays minimal (rebuild `dist/` only)

Plus a small **schema-optimization pass** (section 0) — targeted indexes matching real queries, not a rewrite.

---

## 0. Schema, from scratch (`code/db/schema.go`)

User granted freedom to redesign the schema. The key enabling insight: **the DB is a derived cache, not a source of truth** — every row in `specs`/`specs_fts`/`spec_tags`/`spec_vectors` is regenerated by scanning the source files (`FullScan`). That means the ~70-line additive-migration system (`runMigrations`, `migrations`, `columnMigration`, `hasColumn`, `schema.go:120-191`) is **over-engineering for this tool**: instead of ALTER-ing old DBs column-by-column across releases, a schema change can just **bump a version and rebuild the cache** — lossless, because the source files are the truth.

### 0a. Replace migrations with a version guard

- Drop `runMigrations` / `migrations` / `columnMigration` / `hasColumn` entirely.
- Add `const schemaVersion = 1` and, in `CreateSchema`: read `PRAGMA user_version`. If it's `0` → fresh DB, run DDL, set `user_version = schemaVersion`. If it's `> 0` and `< schemaVersion` → the cache is stale: `DROP` the derived tables (or delete the DB file) and re-run DDL, then set the version. A follow-up `scan` repopulates. (Net: `-~70 lines`, no per-column ALTER bookkeeping ever again.)

### 0b. The full new `schemaSQL`

Column order matters: keep the large `content` **last** in `specs` so narrow scans (name/project/modified/vector joins) never page through content overflow. Add `modified_unix INTEGER` for a correct, indexable `recent` sort (TEXT `modified` stays for display). Vectors and edges are first-class from day one. Feature tables (`repos`, `external_graphs`, `meta`) keep all columns the graphify / code-review-graph commands rely on — those are folded straight into the base DDL (previously reached via migrations).

```sql
CREATE TABLE IF NOT EXISTS repos (
  id INTEGER PRIMARY KEY, name TEXT UNIQUE NOT NULL, path TEXT UNIQUE NOT NULL,
  graph_path TEXT, graph_mtime INTEGER, graph_node_count INTEGER, graph_last_seen INTEGER,
  code_graph_path TEXT, code_graph_mtime INTEGER, code_graph_node_count INTEGER
);

CREATE TABLE IF NOT EXISTS external_graphs (
  name TEXT PRIMARY KEY, graph_path TEXT NOT NULL, graph_mtime INTEGER,
  node_count INTEGER, added_at INTEGER, kind TEXT NOT NULL DEFAULT 'graphify'
);

CREATE TABLE IF NOT EXISTS specs (
  id            INTEGER PRIMARY KEY,
  repo          TEXT NOT NULL,
  path          TEXT NOT NULL,
  project       TEXT NOT NULL,
  name          TEXT NOT NULL,
  title         TEXT NOT NULL,
  tags          TEXT DEFAULT '',
  summary       TEXT DEFAULT '',
  fullpath      TEXT NOT NULL,
  modified      TEXT NOT NULL,               -- display string (unchanged)
  modified_unix INTEGER NOT NULL DEFAULT 0,  -- epoch, for fast/correct recent sort
  size          INTEGER NOT NULL,
  ext           TEXT NOT NULL,
  content       TEXT DEFAULT '',             -- LARGE; kept last so narrow scans skip overflow
  UNIQUE(repo, path)
);

CREATE VIRTUAL TABLE IF NOT EXISTS specs_fts USING fts5(
  repo, name, title, tags, summary, content,
  content='', tokenize='porter unicode61'
);

CREATE TABLE IF NOT EXISTS spec_tags (
  spec_id INTEGER NOT NULL,
  tag     TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS spec_vectors (
  spec_id INTEGER PRIMARY KEY,   -- = specs.id (same rowid join FTS uses)
  repo    TEXT NOT NULL,         -- denormalized: semantic scan filters w/o joining big specs rows
  dim     INTEGER NOT NULL,
  vec     BLOB    NOT NULL       -- dim * float32, little-endian
);

CREATE TABLE IF NOT EXISTS spec_edges (   -- optional precomputed kNN cache (graph cmd)
  src_spec_id INTEGER NOT NULL,
  dst_spec_id INTEGER NOT NULL,
  weight      REAL    NOT NULL,           -- cosine similarity 0..1
  PRIMARY KEY (src_spec_id, dst_spec_id)
);

CREATE TABLE IF NOT EXISTS meta ( key TEXT PRIMARY KEY, value TEXT );

CREATE INDEX IF NOT EXISTS idx_specs_name_lower  ON specs(LOWER(name));
CREATE INDEX IF NOT EXISTS idx_specs_project     ON specs(project);              -- WHERE project=? / GROUP BY project
CREATE INDEX IF NOT EXISTS idx_specs_modified    ON specs(modified_unix DESC);   -- recent ORDER BY ... LIMIT
CREATE INDEX IF NOT EXISTS idx_tags              ON spec_tags(tag);              -- GROUP BY tag / COUNT(DISTINCT tag)
CREATE INDEX IF NOT EXISTS idx_tags_lower        ON spec_tags(LOWER(tag));       -- WHERE LOWER(tag)=?
CREATE INDEX IF NOT EXISTS idx_spec_tags_spec_id ON spec_tags(spec_id);          -- JOIN by spec_id
CREATE INDEX IF NOT EXISTS idx_spec_vectors_repo ON spec_vectors(repo);          -- repo-scoped semantic scan
CREATE INDEX IF NOT EXISTS idx_spec_edges_src    ON spec_edges(src_spec_id);
```

### 0c. Deliberate changes vs. today

- **Removed FK constraints** on `spec_tags` (and none added on `spec_vectors`): consistency is guaranteed by the atomic rebuild, so FKs only cost insert overhead. `PRAGMA foreign_keys=ON` can drop from `Open()`.
- **New indexes** `idx_specs_project` + `idx_specs_modified` fill the only two real gaps found in `db/query.go` (`WHERE project=?` at `:242,285`; `ORDER BY modified DESC` at `:451`).
- **`ANALYZE;`** runs at the end of `FullScan` so the planner uses the new indexes; **`PRAGMA mmap_size=268435456`** added to `Open()` (`schema.go:93-100`) for faster reads (graceful fallback). *(mmap optional.)*
- **Kept as-is:** `UNIQUE(repo,path)` (serves `repo=?` prefix); `idx_tags` raw (used by `GROUP BY tag`); the `specs.tags` + `spec_tags` + FTS `tags` triple-storage (all three read — display, faceting, search).
- **Requires `extract` change:** populate `Spec.ModifiedUnix = info.ModTime().Unix()` where `formatMtime` is set, so `modified_unix` is filled at insert.

## 1. Core vector search

### 1b. Embedder — new package `code/embed/embed.go`
Pure Go, dependency-free, deterministic. Feature-hashing bag-of-words:
- `const Dim = 256`
- `func Embed(text string) []float32` — lowercase, split on non-alphanumerics (reuse the same simple tokenization style already used for tags/summary in `extract`), hash each token (`hash/fnv` FNV-1a) → bucket `h % Dim`, increment; optionally sign-hash bit to reduce collisions; then **L2-normalize**. Empty/whitespace text → zero vector (caller skips).
- `func Encode(v []float32) []byte` / `func Decode(b []byte) []float32` — little-endian via `encoding/binary` + `math.Float32bits`/`Float32frombits`.
- `func Cosine(a, b []float32) float32` — dot product (both already L2-normalized ⇒ dot == cosine); guard dim mismatch → return 0.

### 1c. Index integration (`code/db/index.go`)
Mirror the existing `batchInsertTags` pattern (`index.go:632-660`): a new `batchInsertVectors(tx, repoName) error` that `SELECT id, title, summary, content FROM specs WHERE repo=?`, embeds `title+"\n"+summary+"\n"+content` per row, and `INSERT OR REPLACE INTO spec_vectors(spec_id,repo,dim,vec) VALUES (?,?,?,?)` (repo denormalized for the repo-scoped semantic scan).
- Call it inside the existing single TX in `FullScan` right after `batchInsertTags` (`index.go:130`) and in `IncrementalScan` after its tag pass (`index.go:~340`) — for incremental, restrict to inserted paths (add `batchInsertVectorsPaths` mirroring `batchInsertTagsPaths`/`chunkPaths`, and delete stale vectors alongside `deleteSpecEntry`).
- Embedding is CPU-cheap (hashing) so doing it in Phase 2 in-TX is fine; no async needed.
- Skip rows whose embedding is a zero vector.

### 1d. Query fusion (`code/db/query.go` + `code/main.go`)
Add a **new opt-in mode** so default behavior is byte-for-byte unchanged. Introduce `func SemanticSearch(db, query, repoFilter, directoryFilter string, k int) ([]SearchResult, error)`:
1. Run the existing FTS5 `Search` to get BM25 candidates (keep top ~200).
2. `qv := embed.Embed(query)`; load `spec_vectors` for the candidate `spec_id`s (or all rows at POC scale), `embed.Cosine` each.
3. **Fuse** BM25 + cosine via Reciprocal Rank Fusion (rank in each list → `1/(60+rank)` summed) — robust to FTS5's negative-rank scale and avoids hand-tuned weights. Populate `SearchResult.Relevance` with the fused score and sort.
- Wire into `main.go`: add a `--semantic` (and/or `--hybrid`) flag parsed in `cmdSearch`, and a `json search --semantic` path in `cmdJSON` (`main.go:1156`). Reuse the `applyGraphAwareRanking` fusion precedent (`main.go:885-919`) as the structural model.

## 2. kNN graph command (`code/main.go`, new `graph`/`vgraph` command)
New top-level case in the dispatch switch (`main.go:45-105`) → `cmdVectorGraph(args)`, mirroring `cmdJSON`'s nested-subcommand style. Emits NetworkX node-link JSON `{"nodes":[{id,label,...}],"links":[{source,target,weight}]}` (same shape as `graph/graph.go:59-68`, D3/Cytoscape-ready).

- **Mode `tag <tag>`**: node set = specs joined to `spec_tags` for that tag (`schema.go:63-71`); edges = kNN within/across the subset via cosine, thresholded (e.g. keep cosine ≥ 0.3 or top-k per node) to avoid a hairball.
- **Mode `search <query>`**: ego graph — embed query → top-k seed specs → optional one-hop expand (each seed's kNN).
- **Precompute vs live:** for POC scale, compute **live** in Go (O(N·rows) brute force, fine for hundreds–low-thousands). Optionally populate `spec_edges` during index (a `buildEdges` pass) for larger corpora / repeat loads — implement the live path first; `spec_edges` is a documented optional optimization.

## Edge cases
- Existing DBs: the `user_version` guard (§0a) detects the old cache and rebuilds it (drop derived tables → re-run DDL); a `scan` repopulates. Safe because the DB is a derived cache of the source files. `spec_vectors` empty until that re-scan → semantic search falls back to FTS-only ordering.
- Zero-vector / empty content → skip insert; cosine guards dim mismatch → 0.
- Incremental update: delete `spec_vectors`/`spec_edges` rows for removed/changed specs in the same TX as `deleteSpecEntry`, then re-embed inserted paths.
- Dim change (if `embed.Dim` ever changes) → mismatched stored vectors ignored (dim check); documented as "rebuild required."
